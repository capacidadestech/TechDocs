1Control de flujo @if · @for · @empty

Definición

Bloques de control de flujo integrados en la plantilla (built-in control flow): renderizan contenido de forma condicional (@if), repiten sobre una colección (@for) o muestran un contenido alternativo cuando esa colección está vacía (@empty). Forman parte de la sintaxis del template desde Angular v17 y no requieren importar ninguna directiva.

La sintaxis moderna de plantillas (Angular v17+) reemplaza a *ngIf / *ngFor. Es parte del lenguaje de la plantilla, más legible y sin necesidad de importar directivas.

  • @for exige track: una clave de identidad por elemento para reconciliar el DOM de forma eficiente (no recrea filas que no cambiaron).
  • @empty es el caso “lista vacía”, integrado dentro del propio @for.
  • @if (expr; as x) captura el valor en una variable; admite @else if / @else.

Patrón (los tres juntos, en la tabla genérica)

<tbody>
  @for (row of rows(); track rowKey(row)) {
    <tr>
      @for (col of columns(); track col.key) {
        <td>
          @if (templateFor(col.key); as tpl) {
            <ng-container [ngTemplateOutlet]="tpl" />
          } @else if (col.type === 'date') {
            {{ dateValue(row, col.key) | date: 'd MMM y' }}
          } @else {
            {{ value(row, col.key) }}
          }
        </td>
      }
    </tr>
  } @empty {
    <tr><td>{{ emptyMessage() }}</td></tr>   // lista vacía
  }
</tbody>

2Standalone + inject()

Definición

Componente standalone: componente, directiva o pipe que declara sus propias dependencias en imports y no pertenece a ningún NgModule. inject(): función que obtiene una dependencia del inyector de DI en el contexto de construcción, como alternativa a recibirla por el constructor.

No hay NgModule: cada componente es standalone y declara sus dependencias en imports. La inyección se hace con la función inject() en lugar del constructor.

  • Menos ceremonia: no se registran declaraciones en módulos; el componente es autocontenido.
  • inject() funciona en campos de clase y funciones → código más conciso y componible.
  • Los servicios usan @Injectable({ providedIn: 'root' }) → singleton de toda la app.

Patrón (componente smart)

@Component({
  selector: 'app-document-list',
  imports: [EmptyState, DataTable, CellFor, Paginator, /* … */],   // sin NgModule
  templateUrl: './document-list.html',
})
export class DocumentList {
  private readonly documentService = inject(DocumentService);   // DI funcional
  private readonly folderService   = inject(FolderService);
  private readonly filters         = inject(DocumentFilterService);
}

3Directivas custom tema débil M1

Definición

Directiva: clase decorada con @Directive que añade comportamiento al DOM. Las de atributo modifican la apariencia o el comportamiento de un elemento existente (eventos, clases, estilos); las estructurales añaden o quitan elementos del DOM operando sobre una <ng-template>.

Implementamos las dos familias: una de atributo (decora un elemento existente) y una estructural (trabaja con <ng-template>).

a) De atributo — appThemeSwatch

Escucha eventos y alterna clases usando el objeto host del decorador (forma v22, sin @HostListener).

@Directive({
  selector: '[appThemeSwatch]',
  host: {
    '(mouseenter)': 'preview()',
    '(click)': 'select()',
    '[class.is-active]': 'isActive()',   // class binding reactivo
  },
})
export class ThemeSwatch {
  readonly appThemeSwatch = input.required<string>();   // id del tema
}

4Signals signal · computed · effect

Definición

Signal: primitiva reactiva que envuelve un valor y notifica automáticamente a quien lo consume cuando cambia. signal() crea un valor mutable; computed() deriva un valor memoizado a partir de otras señales; effect() ejecuta un efecto secundario cada vez que cambian las señales que lee.

El modelo de reactividad de Angular moderno. Estado granular que avisa a quien lo consume cuando cambia, sin zone.js de por medio.

  • signal(): estado mutable reactivo — se lee como función x() y se cambia con .set() / .update().
  • computed(): valor derivado, memoizado; se recalcula solo cuando cambian sus dependencias.
  • effect(): efecto secundario que corre cuando cambia lo que lee (sincronizar, reaccionar).

Patrón (los tres en el listado)

// signal() — estado base
protected readonly page = signal(1);
protected readonly pageSize = signal(5);

// computed() — derivado (filtra por carpeta + búsqueda + estado + tipo)
protected readonly filtered = computed(() =>
  this.documentService.documents().filter(/* … */));
protected readonly paged = computed(() => {
  const start = (this.page() - 1) * this.pageSize();
  return this.filtered().slice(start, start + this.pageSize());
});

// effect() — al cambiar de carpeta o filtros, vuelve a la página 1
constructor() {
  effect(() => {
    this.folderService.selectedFolderId();
    this.filters.term(); this.filters.status(); this.filters.type();
    this.page.set(1);
  });
}

5Inputs / Outputs smart / dumb

Definición

API basada en signals para la comunicación entre componentes: input() declara una propiedad de entrada (padre → hijo) como señal de solo lectura, y output() declara un emisor de eventos (hijo → padre). Reemplazan a los decoradores @Input / @Output.

input() y output() (signal-based) reemplazan a @Input / @Output. Los componentes dumb solo reciben datos por input() y notifican por output(); el smart orquesta estado y servicios.

  • Un input() es un signal de solo lectura → se integra con computed() sin esfuerzo.
  • Admite input.required<T>(), valor por defecto y alias.
  • Esta separación smart/dumb habilita OnPush en M5 sin refactor.

Patrón (componentes dumb)

// DataTable (dumb): solo recibe datos
readonly columns      = input.required<TableColumn[]>();
readonly rows         = input.required<readonly unknown[]>();
readonly emptyMessage = input<string>('No hay resultados.');   // con default

// Modal (dumb): recibe heading, emite close
readonly heading = input('');
readonly close   = output<void>();
